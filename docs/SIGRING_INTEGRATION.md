# 시그링(SIGRING) 스마트링 연동 기획 — 늘곁 적용안

> 근거: 시그링 공식 사이트(sigring.co.kr — 홈, shop, ai-solution, about/science·safety·trust)의 **공개 정보만** 사용했습니다(2026-11-26 확인).
> 제조사(시그넘헬스)와 협의한 내용이 아닙니다. 기능·데이터 항목은 협약 단계에서 반드시 다시 확인해야 합니다.
> 시연의 "SIGRING100 (연동 가정 · DEMO)" 기기와 수치는 모두 합성 데이터입니다.

## 1. 제품 요약 (사이트 기준)

| 구분 | 내용 |
|---|---|
| 제품·회사 | SIGRING100, 시그넘헬스. 2027년 1월 출시 예정(가격 미정) |
| 센서 | PPG 3파장(녹·적·적외), 3축 가속도, 3축 자이로, 피부 온도 |
| 지표 | 심박, HRV(RMSSD·SDNN), 피부 온도의 하루 흐름, 걸음·활동, 수면 시간·단계, 스트레스, **활력 지수**(6개 하위 지수 종합, 60~99), 생체리듬 규칙성. SpO₂는 센서 설명에만 있고 수치 제공 여부는 불명확 |

| 데이터 경로 | 링 → (BLE) 휴대폰 앱이 점수 계산 → 국내 클라우드(AWS 서울) 백업. 원본 파형은 링 밖으로 나가지 않음 |
| 연동 | **공개 API·SDK·데이터 내보내기 없음.** 연구·제휴 문의 채널만 있음 |
| 인증 | 의료기기 아님(사이트 명시). KC 전파·배터리 안전, CE·FCC |
| 하드웨어 | 배터리 5~9일, 무선 충전, IP68·5ATM, 2.9~3.9g |
| 보호자 기능 | "소중한 사람 챙기기": 서로 동의한 가족에게 아침마다 활력·수면 요약과 평소와 다를 때의 알림을 공유 |

## 2. 늘곁에서 할 수 있는 것 / 할 수 없는 것

**할 수 있는 것 (일 단위 "평소 대비" 돌봄)**
1. **아침 안부 요약**: 사례관리자가 담당 링 착용자의 어제 활력 지수·수면·걸음·피부 온도를 *본인 평소(14일 중앙값)*와 비교해 한 화면에서 확인. 시그링의 가족 공유 기능을 사례관리자용으로 옮긴 형태
2. **확인 필요 신호(진단 아님)**
   - 활력 지수 하락: 평소보다 10점 이상 낮을 때
   - HRV 감소: 평소의 70% 미만일 때(평소 15ms 이상인 경우만)
   - 피부 온도 상승: 평소 대비 +1.0℃ 이상일 때. 체온이 아니므로 "발열 여부를 전화로 확인"하도록 안내
   - 기존 활동량 감소·수면 변화·착용 부족·요약 미수신 신호도 그대로 적용
3. **착용 지속 관리**: 배터리가 5~9일이라 충전 공백으로 미착용·미수신이 생기기 쉬움. 기존 `low_wear`·`no_data` 신호를 쓰고, 방문할 때 충전 상태를 확인하도록 안내
4. **서비스 효과 추적(후속)**: 식사·운동·사회참여 서비스를 시작한 뒤 활동·수면·활력 추세를 사례 모니터링 기록에 첨부

**할 수 없는 것 (반드시 다른 수단과 함께)**
- 낙상·SOS 긴급 호출 → 응급안전안심서비스 장비, 스마트워치 등과 **병행**
- 실시간 위치 → GPS가 없으므로 지도에는 **지정 위치(거주지)만** 표시
- 실시간 측정값 경보 → 휴대폰 앱을 거쳐 동기화되므로 실시간을 보장할 수 없음. 관제 화면의 측정값 경보 대상이 아님
- 진단·의료 판단 → 의료기기가 아님

## 3. 구현 내용 (이번 변경)

| 항목 | 내용 |
|---|---|
| 기기 프로필 `lib/domain/devices.ts` | `generic_ring` · `generic_watch` · `sigring100`. 측정 항목, 미확인 항목, 실시간 여부, 위치·낙상·SOS 지원 여부, 동기화 방식, 의료기기 여부, 주의 문구 |
| 등록 검증 | 프로필이 측정하지 않는 항목(예: 시그링의 낙상·SOS·체온)은 **동의 항목으로 받지 않음**(400, `unsupported`). 기기 종류와 프로필이 다르면 거부 |
| 수신 규격 0.2 | 일 요약에 `sleepDeepMinutes`, `sleepRemMinutes`, `hrvRmssd`, `skinTempDeviationC`, `stressIndex`, `vitalityScore` 추가. 0.1로 이 항목을 보내면 400. 동의 항목 대조는 기존과 같음 |
| 동의 항목 | `hrv`, `skin_temp`, `stress`, `vitality` 추가 (migration 009) |
| 위치 | 위치 기능이 없는 프로필은 위치 동의 등록 거부(400), 게이트웨이 위치 수신 거부(422 `DEVICE_HAS_NO_LOCATION`) |
| 관제 화면 | 일 요약 기기는 실시간 측정값이 없어도 "갱신 지연(주의)"으로 분류하지 않음(48시간 이내 동기화 = 연결). 팝업에 "낙상·SOS·위치 기능 없음" 안내. **아침 안부 요약** 패널 추가 |
| 사례 웨어러블 탭 | 기기 프로필 선택, 프로필 주의 문구, 활력·HRV·피부 온도 열 |
| 시연 데이터 | C-0015(활력↓·피부 온도↑ 신호), C-0016(평소와 비슷), C-0017(짧은 수면 패턴) |

## 4. 연동 방식 (협약 필요)

```
[SIGRING100] ─BLE─▶ [시그링 앱] ─▶ [시그넘헬스 서버] ══(서버 간 연계, 협약)══▶ [늘곁 게이트웨이 규격 0.2]
                                         │ 대상자 동의 범위만 · 일 요약만 · 원본 파형 없음
```
- 공개 API가 없으므로 **B2G 데이터 연계 협약**이 먼저 필요합니다. 늘곁은 기기 제조사와 상관없이 같은 게이트웨이 규격(`/api/integrations/wearables/daily-summaries`, schemaVersion 0.2)으로 받습니다.
- 대안: 지자체가 지정한 게이트웨이 사업자가 여러 제조사 데이터를 모아 늘곁 규격으로 보내는 방식(제조사별 개별 연동 부담 감소).
- 앱 사용 요건(iOS 18+ / Android 12+ 휴대폰)이 어르신 보급의 장벽입니다. 공용 허브 기기나 보호자 휴대폰으로 동기화하는 방식을 제조사와 협의해야 합니다.

## 5. 제조사에 확인할 질문

1. 기관(지자체) 대상 데이터 연계 API·협약 모델이 있는지. 범위는 일 요약인지, 시간 단위까지 가능한지
2. SpO₂ 수치 제공 여부, 활력 지수 6개 하위 지수의 원값 제공 여부와 산출 방식 문서
3. 피부 온도 "평소 대비" 값의 정의(기준 기간, 단위), 수면 단계 정확도 자료
4. 휴대폰 없이 동기화할 수 있는지(허브·게이트웨이), 고령자용 앱 모드
5. 가명처리 연구 데이터 정책(10년 보관)과 지자체 위탁 데이터의 분리, 파기 절차
6. 낙상·SOS 기능 로드맵, 또는 응급안전안심서비스 장비와의 연계 가능성
7. 대량 보급 단가, 분실·파손 정책, 배터리 교체 주기

## 6. 개인정보·법

- 건강 관련 항목은 항목별 별도 동의(개인정보 보호법 제23조)를 받습니다. 프로필이 측정하지 않는 항목은 아예 동의 대상에서 뺍니다.
- 제조사 앱에서 대상자가 동의한 범위와 지자체 위탁 범위가 일치해야 합니다(이중 동의·고지).
- 시그링은 의료기기가 아니므로 화면·문서에서 "진단·응급" 표현을 쓰지 않습니다. 신호는 모두 "확인 필요"입니다.
