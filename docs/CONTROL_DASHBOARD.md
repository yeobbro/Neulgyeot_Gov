# 통합 관제 (Phase 1) — 대상자 위치·상태 통합 현황

> 화면: `/control` (지자체 관리자·사례관리자). 인물·위치·수치는 모두 합성 데이터입니다.
> 선행: [WEARABLE_INTEGRATION.md](WEARABLE_INTEGRATION.md) (Phase 0: 일 요약·확인 필요 신호)

## 1. 목적과 원칙

| 원칙 | 구현 |
|---|---|
| **의료 판단·응급 관제 아님** | 상태 분류는 "담당자가 먼저 확인할 대상"을 고르는 기준이며 진단이 아님. 화면 상단과 출동 폼에 119·응급안전안심서비스 우선 안내 |
| **임시 측정값 기준** | `PROVISIONAL_VITAL_THRESHOLDS` (`lib/domain/control.ts`)는 `reviewed: false`. **실운영 전 의료진 검토 후 교체 필수** |
| **현재 위치 ≠ 지정 위치** | 현재 위치는 *위치정보 별도 동의* + *30분 이내 수신* 둘 다 있을 때만 표시. 그 밖에는 지정 위치(거주지 근사)를 점선 마커로 표시하고 이유(동의 없음·갱신 지연·수신 없음)를 팝업에 표시 |
| **동의 범위 밖 데이터는 받지 않음** | 측정값의 각 항목(심박·체온·SpO₂·낙상·SOS)은 웨어러블 동의 항목과 대조, 하나라도 벗어나면 전체 거부(422). 위치는 위치 동의가 없으면 저장하지 않음 |
| **권한** | 관리자: 전체 / 사례관리자: 담당 권역만 / 제공기관·감사자: 접근 불가. 조회·조치는 감사 로그(메타데이터만) |

## 2. 화면 구성 (목업 대응)

| 영역 | 내용 |
|---|---|
| KPI 6종 | 전체 대상자 · 실시간 모니터링(기기+120분 이내 측정값) · 주의 · 긴급 · 서비스 진행중(STARTED 의뢰) · 오늘 현장 방문(방문 일정+출동) |
| 지도 | OSM 타일 직접 렌더링(라이브러리 없음), 드래그·휠·버튼 확대. 탭: **실시간 위치 현황** / **지정 위치(거주지)**. 상태·서비스 유형 필터, 이름·사례번호·동 검색 |
| 팝업 | 상태, 위치 표시 근거, 최신 측정값(동의 항목만), 열린 알림, 출동 상태, `상세보기` → 사례 웨어러블 탭, `현장 출동요청` |
| 상태 현황 | 도넛 + 범례. 상태는 대상자당 하나: 긴급 > 주의 > 서비스 중 > 정상 > 미연결 |
| 주요 대상자 모니터링 | 우선순위 상위 6명, 심박·체온, 위치/서비스 |
| 실시간 이슈 알림 | 측정값 알림(대응 시작·종결, 종결은 확인 내용 필수) + 일 요약 신호(대상자당 1행) |
| 서비스 운영 현황 | 오늘 방문을 서비스군(방문요양·가사 / 방문간호·건강 / 식사 / 이동 / 기타)별 집계 — 기존 서비스 코드만 사용 |
| 현장 인력 관리 | 사례관리자별 담당·긴급/주의·진행 중 출동·오늘 완료, 제공기관별 오늘 방문 현황, "나에게 온 출동요청"(수락 → 현장 도착 → 완료) |

60초마다 자동 갱신(탭이 보일 때만). 웹소켓은 Phase 2.

## 3. 상태 분류

```
긴급     열린 urgent 알림 (SOS·낙상·측정값 긴급 범위)
주의     열린 caution 알림 · 열린 일 요약 신호 · 기기는 있는데 측정값이 120분 넘게 없음
서비스 중 오늘 방문 서비스가 진행 중
정상     기기 연결 + 최근 측정값 + 위 항목 없음
미연결   등록된 기기 없음
```
임시 기준 (의료진 검토 전): 심박 ≥120 또는 ≤45 → 긴급, ≥100 또는 ≤50 → 주의 / 체온 ≥38.5 → 긴급, ≥37.5 또는 ≤35.5 → 주의 / SpO₂ <90 → 긴급, <94 → 주의.
알림은 (사례, 종류)별로 하나만 열림. 같은 상황이 반복 수신되면 새 알림 대신 기존 알림의 마지막 수신 시각과 문구를 갱신함. 긴급 알림이 새로 열리면 주 담당자에게 알림을 보냄.

## 4. 연계 규격 (DEMO v0.1)

| 엔드포인트 | 권한(scope) | 내용 |
|---|---|---|
| `POST /api/integrations/wearables/readings` | `wearables:write` | `{schemaVersion:"0.1", deviceRef, readings:[{measuredAt, heartRate?, bodyTempC?, spo2?, event?: "fall"\|"sos"}]}` (최대 120건, 최근 24시간 이내) |
| `POST /api/integrations/locations` | `locations:write` | `{schemaVersion:"0.1", deviceRef, fixes:[{measuredAt, latitude, longitude, accuracyM?}]}` (최대 60건) |

오류: 400 `VALIDATION_FAILED` · 404 `DEVICE_NOT_REGISTERED` · 422 `CONSENT_NOT_ACTIVE` / `CONSENT_SCOPE_VIOLATION`(fields) / `LOCATION_CONSENT_NOT_ACTIVE`.

직원 API: `POST /api/cases/:id/location`(지정 위치) · `POST /api/cases/:id/location/consent` · `.../consent/withdraw` · `POST /api/cases/:id/dispatches` · `POST /api/dispatches/:id` · `POST /api/control-alerts/:id`.

## 5. 데이터 (migration 008)

`care_locations` · `location_consents`(보관 1~720시간) · `location_fixes` · `wearable_readings` · `control_alerts` · `field_dispatches`(사례당 진행 중 1건) · `service_visits`. 모두 RLS. 위치·측정값은 앱 역할이 INSERT/SELECT만 가능하며, 삭제는 소유자 권한의 파기 배치가 맡음(후속 과제). 웨어러블 동의 항목에 `temperature` 추가.

## 6. 법·운영 검토 필요 (실운영 전)

- 개인위치정보 수집·이용: 위치정보법상 동의·고지, 위치정보사업자/위치기반서비스사업자 신고 해당 여부, 보호자 동의(의사능력 제한 대상자)
- 측정값 기준: 의료진 검토, 대상자별 기준 조정(기저질환·복약) 필요성
- 지도 타일: 시연은 OSM 공개 타일. 운영은 계약된 타일 제공자(예: 브이월드) 또는 자체 타일 서버로 교체하고 CSP `img-src`도 함께 변경
- 출동요청은 내부 업무 요청이며 119·응급안전안심서비스 신고를 대신하지 않음. 이 안내 문구를 운영 매뉴얼에도 반영
